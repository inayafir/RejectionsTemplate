===============================================================================
CHSS REJECTION LETTER - SERVLET MAPPINGS
===============================================================================

The module has TWO servlets. Both use Servlet 3.0 @WebServlet annotations, so
no web.xml changes are needed when annotation scanning is enabled (the default
for an Eclipse Dynamic Web Project on Tomcat).

If the Sandesh project's web.xml sets metadata-complete="true" (annotation
scanning OFF), register the same components in web.xml instead. Copy/paste the
following blocks into the existing web/WEB-INF/web.xml and remove the
annotations (or keep them - do NOT double-register the same url-pattern).

The patterns below are RELATIVE to the webapp context (the module never
hardcodes a context path; the JSPs use ${pageContext.request.contextPath} for
every link/action). There is NO startup listener and no other component.

--------------------------------------------------------------------------------
1) Employee search (autocomplete JSON for the generate page)
--------------------------------------------------------------------------------

    <servlet>
        <servlet-name>employeeSearch</servlet-name>
        <servlet-class>com.ursc.chss.servlet.EmployeeSearchServlet</servlet-class>
    </servlet>
    <servlet-mapping>
        <servlet-name>employeeSearch</servlet-name>
        <url-pattern>/employee-search</url-pattern>
    </servlet-mapping>

--------------------------------------------------------------------------------
2) Main workflow servlet (generate / view / edit / download / print / regenerate)
--------------------------------------------------------------------------------

    <servlet>
        <servlet-name>letterServlet</servlet-name>
        <servlet-class>com.ursc.chss.servlet.LetterServlet</servlet-class>
    </servlet>
    <servlet-mapping>
        <servlet-name>letterServlet</servlet-name>
        <url-pattern>/generate</url-pattern>
    </servlet-mapping>
    <servlet-mapping>
        <servlet-name>letterServlet</servlet-name>
        <url-pattern>/view/*</url-pattern>
    </servlet-mapping>
    <servlet-mapping>
        <servlet-name>letterServlet</servlet-name>
        <url-pattern>/edit/*</url-pattern>
    </servlet-mapping>
    <servlet-mapping>
        <servlet-name>letterServlet</servlet-name>
        <url-pattern>/download/*</url-pattern>
    </servlet-mapping>
    <servlet-mapping>
        <servlet-name>letterServlet</servlet-name>
        <url-pattern>/print/*</url-pattern>
    </servlet-mapping>
    <servlet-mapping>
        <servlet-name>letterServlet</servlet-name>
        <url-pattern>/regenerate/*</url-pattern>
    </servlet-mapping>

--------------------------------------------------------------------------------
Renaming the URL patterns
--------------------------------------------------------------------------------
The short patterns above (/generate, /view/*, ...) may collide with an existing
Sandesh servlet. If so, rename them together (for example to /chss/generate,
/chss/view/*, ...) in BOTH places:

1. The @WebServlet annotation (LetterServlet.java / EmployeeSearchServlet.java)
   - and/or the web.xml url-pattern blocks above, and
2. The matching link/action/fetch in the JSPs:
   - web/generate.jsp       form action + autocomplete fetch
   - web/view-letter.jsp    iframe src + Download/Print/Edit/Regenerate links

The JSPs already use ${pageContext.request.contextPath} for every link, and
generate.jsp's autocomplete uses CONTEXT_PATH + '/employee-search?q=...'.
