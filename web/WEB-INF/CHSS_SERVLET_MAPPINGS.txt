===============================================================================
CHSS REJECTION LETTER - SERVLET MAPPINGS
===============================================================================

The module's servlets use Servlet 3.0 @WebServlet / @WebListener annotations, so
no web.xml changes are needed when annotation scanning is enabled (the default
for an Eclipse Dynamic Web Project on Tomcat).

If the Sandesh project's web.xml sets metadata-complete="true" (annotation
scanning OFF), register the same components in web.xml instead. Copy/paste the
following blocks into the existing web/WEB-INF/web.xml and remove the
annotations (or keep them - do NOT double-register the same url-pattern).

All URLs are scoped under /chss/... to avoid colliding with existing Sandesh
servlets.

--------------------------------------------------------------------------------
1) Context listener (initialises DAOs, seeds rejection reasons, storage dir)
--------------------------------------------------------------------------------

    <listener>
        <listener-class>com.ursc.chss.listener.AppContextListener</listener-class>
    </listener>

--------------------------------------------------------------------------------
2) Employee search (autocomplete JSON for the generate page)
--------------------------------------------------------------------------------

    <servlet>
        <servlet-name>employeeSearch</servlet-name>
        <servlet-class>com.ursc.chss.servlet.EmployeeSearchServlet</servlet-class>
    </servlet>
    <servlet-mapping>
        <servlet-name>employeeSearch</servlet-name>
        <url-pattern>/chss/employee-search</url-pattern>
    </servlet-mapping>

--------------------------------------------------------------------------------
3) Main workflow servlet (generate / view / edit / download / print / regenerate)
--------------------------------------------------------------------------------

    <servlet>
        <servlet-name>letterServlet</servlet-name>
        <servlet-class>com.ursc.chss.servlet.LetterServlet</servlet-class>
    </servlet>
    <servlet-mapping>
        <servlet-name>letterServlet</servlet-name>
        <url-pattern>/chss/generate</url-pattern>
    </servlet-mapping>
    <servlet-mapping>
        <servlet-name>letterServlet</servlet-name>
        <url-pattern>/chss/view/*</url-pattern>
    </servlet-mapping>
    <servlet-mapping>
        <servlet-name>letterServlet</servlet-name>
        <url-pattern>/chss/edit/*</url-pattern>
    </servlet-mapping>
    <servlet-mapping>
        <servlet-name>letterServlet</servlet-name>
        <url-pattern>/chss/download/*</url-pattern>
    </servlet-mapping>
    <servlet-mapping>
        <servlet-name>letterServlet</servlet-name>
        <url-pattern>/chss/print/*</url-pattern>
    </servlet-mapping>
    <servlet-mapping>
        <servlet-name>letterServlet</servlet-name>
        <url-pattern>/chss/regenerate/*</url-pattern>
    </servlet-mapping>

--------------------------------------------------------------------------------
URL conflicts
--------------------------------------------------------------------------------
If Sandesh already uses any of the /chss/... patterns above, change the
url-pattern in BOTH places: the @WebServlet annotation (and/or this web.xml
block) AND the matching link/action/fetch in the JSPs. The JSPs use
${pageContext.request.contextPath} for every link, and generate.jsp's autocomplete
uses CONTEXT_PATH + '/chss/employee-search?q=...'.
